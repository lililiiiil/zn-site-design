## 제출 설정 — contig 아니다

⚠ **이 문서 초판에 contig 문자열을 적었는데 폐기했다.** contig 는
RFdiffusion **v1** 방식이고, 그걸 손으로 정하다 native 의 79+62 잔기를
30+24 로 눌렀던 게 4라의 실패다. RFD3 는 `unindex` 로 그 실패를
구조적으로 없앴다 — **모티프의 사슬 내 위치를 모델이 정한다.**
([[5라 과정#5.2 바뀐 것 — 4라운드 대비]])

따라서 링커 길이를 정할 일이 없고, "긴 링커 한가운데 고정점" 같은
걱정도 성립하지 않는다. 2CBA 의 잔기 간격(126 결번 포함)은 제출에
쓰이지 않는다.

실제 제출 형식은 `rfd3/rfd3_r5_1.json` 과 같은 JSON 이다. 이번 것:

- `rfd3/rfd3_r8_full.json` — 11잔기
- `rfd3/rfd3_r8_lean.json` — 8잔기

```json
{
  "ca_mimic_r8_full": {
    "input": "motif_C_v1.pdb",
    "ligand": "ZN",
    "unindex": "A92,A94,A96,A106,A117,A119,A121,A143,A198,A199,A209",
    "length": "150-220",
    "select_fixed_atoms": { "...": "TIP" }
  }
}
```

`length` 는 5라와 같은 `150-220` 으로 뒀다. 모티프만 변수로 두려면
길이를 건드리지 않는 게 맞다 (5라 결과 173·214 잔기, native 258).

`num_designs` 16 / `diffusion_batch_size` 8 → 벌당 2 job.
Classifier-free guidance 끔. `select_buried` 미사용.

## 제출 전에 정해야 하는 것

### 1. Val143 를 뺄까 (권고: 안 뺀다 — 초판에서 뒤집었다)

초판에 "뺀다"고 적은 근거가 틀렸다. "가장 긴 링커 한가운데 혼자 박힌
고정점이라 만족시키기 어렵다"고 썼는데, **`unindex` 에는 링커가 없다.**
위치를 모델이 정하므로 143 의 사슬 내 고립도 같은 건 제출에 존재하지 않는다.
contig 를 전제한 추론이었고 도구를 잘못 짚었다.

링커 요인을 빼면 143 의 비용은 "맞춰야 할 TIP 하나 추가"뿐이고, 그건
다른 셋과 같다. 이득은 작지만(+0.006) 비용도 그만큼 작아서 뺄 이유가 없다.

### 2. Leu198 은 기여 0 인데 왜 남기나

포켓 기준으로는 넣을 이유가 없다(+0.000). 남기는 이유는 다른 데 있다 —
198 이 들어가면 **Thr199 가 단독 세그먼트에서 2잔기 세그먼트가 된다.**
Thr199 가 백본에는 이식되는데 서열로 안 접히는 게 2~4라의 알려진 실패이고
([[구조, 지표 정리]] 1장·2.3절), 단독 고정점이 그 원인 후보다. 이건 가설이고
이번 라운드가 그 시험이다.

### 3. 모티프 잔기 11개 — 이식 단계는 여유가 있다

"고정이 많을수록 제약이 심해진다"는 맞는 원칙인데, **RFD3 의 이식 단계에는
지금 여유가 있다.** 5라 측정 ([[5라 과정#5.3 백본 생성 (RFD3)]]):

| 항목 | 참조 (2CBA) | 5라 백본 7잔기 |
|---|---|---|
| His 질소–Zn | 2.10~2.12 Å | **2.10~2.12, 16/16** |
| Thr OG1–Zn | 3.94 Å | **3.94, 16/16** |
| 리간드 충돌 | — | **0, 16/16** |

정렬 RMSD 0.002 Å. TIP 고정이 원자 단위로 작동했고 **7/7 을 16백본 전부에서
완벽히 만족**했다. Thr199 가 안 접힌 건 2~4라(contig/v1) 얘기고, RFD3 로
넘어온 5라에서는 이식이 문제가 아니었다.

현재 병목은 그 아래다 — 5라 `pass` 0/275 (`water_clash` 평균 5.16),
6라 진단은 `lone_pair_dev`(AF3 곁사슬 예측). 즉 **모티프 잔기를 줄여서
지키려는 단계가 지금 막히는 단계가 아니다.**

11잔기의 진짜 위험은 다른 데 있다: TIP 11개를 동시에 만족하는 백본을
찾아야 하므로 **쓸 만한 백본 수가 줄 수 있다**(designability). 이식 실패가
아니라 수율 문제로 나타난다. 이건 측정된 적이 없고, 그래서 두 벌 비교가
값을 한다.

쿼터가 10작업/월이므로, 11잔기 한 벌에 전부 걸지 말고 **두 벌로 갈라
비교하는 쪽을 권고한다**:

| 벌 | 모티프 파일 | 묻는 것 |
|---|---|---|
| C-full | `reference/motif_C_v1.pdb` (11잔기) | 벽을 다 고정하면 접히는가 |
| C-lean | `reference/motif_C_lean.pdb` (8잔기) | 효과의 79% 를 잔기 1개로 얻는가 |

5라와 같이 `num_designs` 16 / `diffusion_batch_size` 8 → 벌당 2 job,
2벌 = **Tamarind 4작업** (쿼터 10 중 4).

설정 파일은 `rfd3/rfd3_r8_full.json`, `rfd3/rfd3_r8_lean.json`.
`length` 는 둘 다 `150-220` 으로 같게 둬서 모티프만 변수로 남긴다.

**두 벌 비교에 교란이 있다.** C-lean 에는 Leu198 이 없어서 Thr199 가 단독
세그먼트로 남는다. 즉 C-full 이 더 잘 접히면 그게 벽 때문인지 198 앵커
때문인지 안 갈라진다. 쿼터를 더 쓸 수 있으면 `B+209+198` 를 세 번째 벌로
넣으면 갈라지지만, 이번 목표는 포켓이므로 교란을 안고 가는 쪽을 권고한다.

### 4. HETATM — 해결됨, 확인할 것 없다

초판에 "RFD3 가 HETATM 을 읽는지 미확인"이라고 적었는데 틀렸다.
`rfd3_r5_1.json` 에 **`"ligand": "ZN"`** 이 있고, [[5라 과정]]에
"RFD3는 리간드를 1급 입력으로 받는다"가 명시돼 있다. ZN 을 버리는 건
v1 쪽 얘기다. 이번 설정 둘 다 `"ligand": "ZN"` 을 그대로 쓴다.
